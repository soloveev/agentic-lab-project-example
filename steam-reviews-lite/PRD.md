# PRD: Steam Reviews

## Контекст

Чтобы понять, что игроки думают об игре, приходится читать сотни отзывов в Steam вручную. Они не сгруппированы по темам, тональность видна только как бинарный флаг «рекомендую / не рекомендую», статистику по темам не собрать. Нужен инструмент, который соберёт отзывы по заданной игре, закодирует их по единому кодбуку и покажет в витрине, где отзывы можно фильтровать, читать и принимать по ним решения.

Стек и код должны быть простыми и объяснимыми: проект делается вместе с AI-агентом, и каждый шаг должен быть понятен человеку.

## Цель v1

Проверить на одной-двух играх, что связка «сбор скриптом → кодирование агентом по кодбуку → локальная витрина» даёт картину, пригодную для принятия решений: универсальный кодбук ложится на реальные отзывы, а витрина позволяет за минуты увидеть, о чём и с какой тональностью пишут игроки.

## Пользователь

Дима — аналитик, работает один, на своём компьютере, в Claude Code. Называет агенту игру и получает базу данных и витрину: в ней смотрит статистику, фильтрует отзывы по тональности и темам, читает их и оставляет пометки-решения.

## Основной сценарий

1. Пользователь в Claude Code вызывает скилл сбора и называет игру (название или app_id).
2. Агент определяет app_id, подтверждает его и запускает скрипт. Скрипт забирает карточку игры и до ~1000 отзывов (русский + английский) через публичные эндпоинты Steam и кладёт в SQLite. Повторный запуск дописывает новые отзывы без дублей.
3. Пользователь вызывает скилл кодирования. Агент батчами читает отзывы, ставит каждому тональность (положительный / отрицательный / нейтральный) и темы из кодбука, пишет теги в базу.
4. Пользователь запускает локальный сервер одной командой и открывает витрину в браузере.
5. В витрине: карточка игры, сводная статистика, список отзывов с фильтрами, карточка отзыва с тегами и полем пометки, которая сохраняется в базу.

## Функциональные требования

Сбор (v1.0):
- Пользователь задаёт игру названием или app_id; агент однозначно определяет app_id и подтверждает его перед сбором.
- Система сохраняет карточку игры: app_id, название, дата выхода, разработчик, издатель, дата сбора.
- Система сохраняет отзывы с полями Steam: id отзыва, язык, текст, флаг «рекомендую», голоса «полезно» и «смешно», часы в игре (всего и на момент отзыва), даты создания и обновления, ранний доступ, получено бесплатно, дата сбора.
- Дедупликация по id отзыва; повторный сбор делает upsert.
- База хранит несколько игр одновременно.
- Сырые ответы Steam сохраняются рядом в JSON, чтобы их можно было переразобрать без повторного сбора.

Кодирование (v1.1):
- Кодбук — отдельный версионируемый документ, универсальный для разных игр: список тем с определениями и примерами; разрабатывается после v1.0 на реальных отзывах.
- Каждый отзыв получает: тональность (pos / neg / neutral), одну или несколько тем, версию кодбука, дату кодирования.
- Агент кодирует батчами и идемпотентно: можно перезапустить, докодировать только новые или перекодировать по новой версии кодбука.
- Флаг Steam «рекомендую» хранится отдельно и служит проверкой: расхождения тональности с флагом попадают в отчёт о качестве кодирования.

Витрина (v1.2):
- Пользователь видит карточку игры и сводку: число отзывов, доли тональностей, топ тем, распределение по датам и языкам.
- Пользователь фильтрует отзывы по тональности, теме, языку, периоду, часам в игре, наличию пометки; сортирует по дате и полезности.
- Пользователь открывает отзыв и видит текст, теги, метаданные Steam.
- Пользователь оставляет пометку и статус решения (например «в работу», «отклонено», «подумать»); пометки сохраняются в SQLite и видны в списке.
- Пользователь переключается между играми.

## Нефункциональные требования

- Всё локально, без хостинга. Python 3.12+, venv, SQLite, FastAPI + Jinja2 / vanilla JS. Без ORM, миграций, фронтенд-фреймворков и очередей.
- Никаких внешних LLM API: кодирует агент Claude Code по скиллу. Steam — только публичные JSON-эндпоинты без ключа.
- Запуск по README: сбор и кодирование — через скиллы в `.claude/skills/`, сервер — одна команда.
- Данные: `data/steam_reviews.sqlite` и `data/raw/<app_id>/*.json`.
- Соблюдать лимиты Steam: пауза между запросами, повтор при ошибке.
- Если есть выбор между простым и масштабируемым, выбрать простое.

## Не входит в v1

- Открытые источники: статьи критиков, пресса, обзоры — v2.
- Сервер, хостинг, загрузка данных агентом на сервер — v3.
- Регистрация, авторизация, командная работа.
- Другие магазины (Epic, консоли) и Steam Web API с ключом.
- Кодирование с помощью внешней или локальной LLM.
- Сравнение игр между собой, экспорт отчётов, уведомления.

## Критерии готовности

- Проект запускается по README в чистом venv.
- Основной сценарий пройден вручную на одной игре: сбор → кодирование → витрина.
- В базе есть отзывы без дублей; повторный сбор не плодит записи.
- Все отзывы выбранной игры закодированы; есть отчёт о расхождениях с флагом Steam.
- Витрина открывается, фильтры и пометки работают, в консоли браузера и сервера нет ошибок.
- Тесты, написанные отдельным агентом, проходят: парсинг ответов Steam, upsert, запись тегов, API витрины.

## Вопросы и риски

- Кодбук не определён и появится только после изучения реальных отзывов. Риск дрейфа определений между сессиями: версия кодбука хранится в каждом теге, определения — в одном файле.
- Качество кодирования агентом: длинные отзывы, сарказм, смешанные языки. Проверяется сравнением с флагом Steam и ручной выборкой.
- Время и стоимость кодирования ~1000 отзывов агентом: батчи по 20–50, идемпотентный перезапуск. Если окажется дорого — кодировать выборку.
- Нейтральный класс: у Steam только бинарный флаг, критерий «нейтрального» надо явно задать в кодбуке.
- Steam: рейт-лимиты, курсорная пагинация (курсор нужно URL-кодировать), региональные различия в карточке игры, дата выхода приходит текстом.
- Где агент может всё усложнить: ORM, миграции, React, очереди задач, микросервисы. Не надо.
- Первая игра для сбора не выбрана.
- Рабочее имя «Steam Reviews»; аббревиатура «DSE» из брифа не расшифрована.
