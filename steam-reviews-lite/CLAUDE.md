# Steam Reviews

Сбор отзывов и карточки игры со Steam, хранение в SQLite, кодирование отзывов агентом по кодбуку, локальная витрина для фильтрации, статистики и решений.

- Требования продукта — [PRD.md](PRD.md). Читай перед тем, как планировать любую фичу.
- Инвентарь, дерево папок, стек, команды — [README.md](README.md). Читай при первом заходе и когда ищешь файл.
- Текущий этап и решения — [progress.md](progress.md), последняя запись. Читай в начале сессии.
- Задачи и бэклог — [kanban.md](kanban.md). Идею пользователя сразу записывай в бэклог.

## Как работаем

1. Пользователь называет версию или фичу из канбана.
2. Ты коротко описываешь в чате, что и как сделаешь: файлы, схема данных, проверка. Ждёшь «ок».
3. Делаешь. Задачи из канбана переводишь «в работу» и «готово» по ходу.
4. **Тесты пишет отдельный агент** (Agent tool), не тот, что писал код. **Запуск тестов — тоже отдельным агентом.**
5. Закрыл версию — запись в progress.md, обновление README и канбана.

## Правила и грабли

- Стек: Python 3.12+, venv в `.venv/`, SQLite, FastAPI + Jinja2 / vanilla JS. Без ORM, миграций, фронт-фреймворков, очередей. Простое важнее масштабируемого.
- Никаких внешних LLM API. Кодирование отзывов — агент Claude Code по скиллу.
- Steam — только публичные JSON-эндпоинты без ключа; пауза между запросами, курсор пагинации URL-кодировать.
- Скиллы проекта — `.claude/skills/<name>/SKILL.md`, скрипты рядом со скиллом.
- Кодбук — `codebook.md`, версионируется; версия кодбука пишется в каждый тег.
- Флаг Steam `voted_up` — не тональность. Тональность ставится по тексту, флаг хранится отдельно для проверки.
- Документы на русском, код и идентификаторы на английском.
