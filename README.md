# Пример организации папки проекта для Agentic Lab

Один и тот же проект показан в двух вариантах: как организовать папку, когда работаешь с AI-агентом (Claude Code, Codex и другие), чтобы проект переживал смену сессий и не расползался. Проект-пример — Steam Reviews: сбор отзывов по игре из Steam, кодирование их по темам и тональности агентом, локальная витрина для просмотра и принятия решений. Кода в репозитории пока нет, только память проекта: с неё и начинается работа.

## Что внутри

| Папка | Подход | Для кого |
|---|---|---|
| [`steam-reviews-lite/`](steam-reviews-lite/) | Лёгкий: пять файлов памяти, план обсуждается в чате | Первый проект с агентом, один сценарий, работа в одиночку |
| [`steam-reviews-sdd/`](steam-reviews-sdd/) | Спек-ориентированная разработка (spec-driven development, SDD): те же пять файлов плюс папка на каждую версию | Есть опыт проектов с агентами, несколько версий, работа неделями |

Обе папки самодостаточны: скопируйте одну и работайте в ней как в корне проекта.

## Что общего

В обеих версиях одинаковый набор файлов памяти, одинаковые правила и один PRD.

- `PRD.md` — что делаем и чего не делаем: контекст, цель первой версии, пользователь, основной сценарий, требования, границы, критерии готовности, риски. Источник правды, от которого отталкивается всё остальное.
- `CLAUDE.md` — до 50 строк: правила проекта, которые нельзя вывести из кода, и поинтеры на остальные файлы. Загружается в контекст агента в каждой сессии.
- `README.md` — навигация: дерево папок, что где лежит, стек, как запустить. Может быть большим.
- `progress.md` — вехи и решения с объяснением «почему». Новая сессия начинается с последней записи.
- `kanban.md` — задачи по версиям: бэклог, следующее, в работе, готово. Идеи записываются сюда, а не теряются в чате.
- `docs/first prompt.md` — промпт, с которого начался проект. По нему агент задал уточняющие вопросы и создал остальные файлы.
- `docs/PRD-template.md` — пустой шаблон PRD с подсказками в каждом разделе. С него начинается PRD любого нового проекта.

Общее правило в обеих версиях: тесты пишет отдельный агент, не тот, что писал код, и запускает их тоже отдельный агент.

## В чём разница

**Лёгкая версия.** Вы называете версию или фичу из канбана, агент коротко описывает в чате, что и как сделает, вы отвечаете «ок» — и агент делает. Всё планирование живёт в чате и в канбане. Дополнительных файлов нет.

**Версия с SDD.** Между «назвать версию» и «сделать» появляется цепочка текстовых артефактов: PRD → спецификация → план → задачи → код. На каждую пачку фич агент создаёт папку `specs/<номер-имя>/` с тремя файлами из `templates/`: `spec.md` (что и зачем, сценарии, требования, критерии приёмки), `plan.md` (как реализуем, файлы, шаги) и `tasks.md` (чекбоксы с критерием проверки). Спецификацию агент показывает первой и без одобрения не пишет ни план, ни код. Задачи зеркалятся в канбан. Зачем это нужно и как устроено в GitHub Spec Kit, Kiro и Tessl, рассказано в [`steam-reviews-sdd/docs/spec-driven-development.md`](steam-reviews-sdd/docs/spec-driven-development.md).

Разница в одном: где живёт точка, в которой ошибку можно поймать дёшево. В лёгкой версии это сообщение в чате, которое через две сессии никто не найдёт. В SDD это файл рядом с кодом, который можно перечитать, поправить и по которому отдельный агент напишет тесты.

## Какой выбрать

Берите лёгкую версию, если это ваш первый или второй проект с агентом, сценарий один, а результат нужен за несколько сессий. Спеки здесь будут стоить дороже, чем сэкономят.

Берите версию с SDD, если версий несколько, работа растянется на недели, в ней участвует больше одного агента или вы уже ловили себя на том, что агент «улучшил» задачу, не спросив. Начать всё равно можно с лёгкой и перейти на SDD позже: файлы памяти совпадают, добавляются только `templates/`, `specs/` и раздел «Процесс» в `CLAUDE.md`.

## Как скопировать себе на компьютер

Нужна только одна из двух папок. Способы — от ручного к автоматическому.

**Способ 0. Сделать свой репозиторий из шаблона.** Репозиторий помечен как шаблон: на его странице есть зелёная кнопка **Use this template** → **Create a new repository**. GitHub создаст копию под вашим именем со всеми файлами, останется склонировать её любым способом ниже и удалить лишнюю папку.

**Способ 1. Скачать архив через интерфейс GitHub.** На странице репозитория нажмите зелёную кнопку **Code**, затем **Download ZIP**. Распакуйте архив, возьмите из него папку `steam-reviews-lite` или `steam-reviews-sdd`, переименуйте её под свой проект и откройте в Claude Code или Codex. Остальное из архива можно удалить.

**Способ 2. Клонировать через git.** В терминале:

```bash
git clone https://github.com/soloveev/agentic-lab-project-example.git
cp -r agentic-lab-project-example/steam-reviews-lite ~/Projects/my-project
cd ~/Projects/my-project
```

Если нужна версия с SDD, вместо `steam-reviews-lite` подставьте `steam-reviews-sdd`. Вместо `~/Projects/my-project` укажите путь к вашей папке.

**Способ 3. Попросить агента.** Откройте Claude Code или Codex в папке, где хотите держать проект, и дайте промпт:

```text
Склонируй https://github.com/soloveev/agentic-lab-project-example.git во временную папку,
скопируй из него папку steam-reviews-lite сюда под именем my-project,
временную папку удали. Затем прочитай my-project/CLAUDE.md и my-project/README.md
и расскажи, с чего начать.
```

Если нужна версия с SDD, замените в промпте `steam-reviews-lite` на `steam-reviews-sdd`. Агент сделает то же, что во втором способе, и сразу прочитает память проекта. Дальше замените содержимое `PRD.md` описанием своего продукта: проще всего дать агенту `docs/first prompt.md` как образец и `docs/PRD-template.md` как шаблон и описать свою идею, а он задаст вопросы и перепишет остальные файлы.
